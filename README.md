# gpt-parser MCP

MCP-сервер для Markdown-файлов игровых кампаний на Python 3.12+ и официальном
[MCP Python SDK v2](https://py.sdk.modelcontextprotocol.io/).
Пакет называется `gpt_parser_mcp`, чтобы не перекрывать импорт SDK `mcp`.
Нужны macOS/Linux с POSIX-блокировками и командой `grep` в `PATH`.

## Установка в venv

Из этой папки:

```bash
make install
make run
```

`make install` создаёт `.venv`, устанавливает Python-пакет и локальный QMD в
`.tools/qmd`, если QMD ещё не установлен. Нужны Python 3.12+, npm и сеть.
`.env` копируется из `.env.example` только при отсутствии; существующие настройки
сохраняются. Модели QMD загружаются отдельно командой `qmd pull`, описанной ниже.
Для установки только Python-части используйте `make install WITH_QMD=0`.
Другой Python можно выбрать через `make install PYTHON=python3.12`.

```bash
make run ARGS='--transport streamable-http'
make run ARGS='--env-file /absolute/path/to/.env'
make clear
```

`make run` использует `.venv` без её активации и передаёт `ARGS` серверу.
По умолчанию настройки берутся из `.env`. `make clear` удаляет `.venv`, артефакты
сборки, Python-кеши и отчёты покрытия из проекта. Кампании, `.env`, QMD и модели
сохраняются. После очистки снова выполните `make install`.

Эквивалентная ручная установка Python-части:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

## Запуск

```bash
# stdio: клиент запускает процесс и общается через stdin/stdout
gpt-parser-mcp

# Эквивалентный запуск как Python-модуля
python -m gpt_parser_mcp

# Streamable HTTP: http://127.0.0.1:8000/mcp
gpt-parser-mcp --transport streamable-http

# Загрузить настройки из указанного файла вместо .env рабочей папки
gpt-parser-mcp --env-file .env
```

В режиме stdio сервер ждёт запросы MCP-клиента. Диагностика направляется в
stderr; stdout используется только протоколом. Остановка — Ctrl+C или закрытие
stdin клиентом. HTTP по умолчанию слушает `127.0.0.1`, использует stateless-режим
и JSON-ответы. Авторизация для внешнего размещения пока не реализована.

Приоритет настроек: аргументы CLI → переменные окружения → `.env` → значения
по умолчанию. CLI и `create_server()` загружают `.env` текущей рабочей папки;
`--env-file` выбирает другой файл. Относительный `BASE_DIR` считается от каталога
выбранного `.env`, даже если процесс запущен из другой рабочей папки.
Для запуска из MCP-клиента укажите абсолютный `--env-file`.

В локальном `.env` уже задано `BASE_DIR=./data`. Для новой установки можно
скопировать `.env.example` в `.env` и выбрать каталог хранения.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MCP_SERVER_NAME` | `gpt-parser-mcp` | Имя сервера |
| `MCP_TRANSPORT` | `stdio` | `stdio` или `streamable-http` |
| `MCP_HOST` | `127.0.0.1` | Адрес HTTP-сервера |
| `MCP_PORT` | `8000` | Порт от 1 до 65535 |
| `MCP_LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `BASE_DIR` | `./data` | Корневой каталог кампаний; также принимается `MCP_BASE_DIR` |
| `MCP_MAX_RESULT_BYTES` | `1048576` | Лимит байтов UTF-8 возвращаемых строк, включая разделители строк |
| `MCP_MAX_RESULT_LINES` | `10000` | Лимит числа возвращаемых строк |
| `MCP_QMD_COMMAND` | `qmd` | Исполняемый файл QMD в PATH или путь относительно `.env` |
| `MCP_QMD_MODE` | `query` | `query`: гибридный/семантический поиск; `search`: только BM25 |
| `MCP_QMD_CACHE_HOME` | `./.cache` | `XDG_CACHE_HOME` для QMD, относительно `.env`; модели QMD 0.9 используют собственный фиксированный путь |
| `MCP_QMD_TIMEOUT` | `300` | Таймаут каждого процесса QMD в секундах, до 3600 |
| `MCP_RECALL_CHUNK_BYTES` | `8192` | Размер фрагмента для QMD, от 256 до 65536 байт |

CLI также принимает `--host`, `--port`, `--help` и `--version`.

## Подключение клиента

Пример для клиента с конфигурацией `mcpServers`; замените `/absolute/path/to/mcp`
на абсолютный путь к этой папке. Активировать venv в клиенте не требуется.

```json
{
  "mcpServers": {
    "gpt-parser": {
      "command": "/absolute/path/to/mcp/.venv/bin/python",
      "args": [
        "-m", "gpt_parser_mcp", "--transport", "stdio",
        "--env-file", "/absolute/path/to/mcp/.env"
      ]
    }
  }
}
```

## Методы MCP

Хранение: `{BASE_DIR}/{name}/{table}.md`. `name` — название кампании,
`table` — имя файла без расширения `.md`. Имена могут содержать Unicode и пробелы,
но не разделители пути, переводы строк или `..` в качестве имени целиком.
Символические ссылки на кампании и таблицы не поддерживаются.

| Метод | Поведение |
| --- | --- |
| `new(name: string): void` | Создать каталог кампании; повторный вызов сохраняет существующие данные |
| `list(): string[]` | Названия непосредственных каталогов кампаний, по алфавиту |
| `listTables(name): string[]` | Имена непосредственных обычных файлов `.md` без расширения, по алфавиту; ссылки, каталоги и служебные файлы исключены |
| `get(name, table, lineId: integer, countLine: integer): string[]` | Прочитать до `countLine` строк, начиная с `lineId` |
| `insert(name, table, line: string): void` | Добавить одну строку в конец; создать файл, если его ещё нет |
| `search(name, table, q: string): string[]` | Вернуть строки, содержащие буквальное `q`, через `grep -F` |
| `searchPage(name, table, q, limit, cursor?)` | Страница совпадений `grep -F` с номерами строк, версией файла и курсором |
| `recall(name, q, limit)` | Ранжированные фрагменты по всем таблицам кампании через QMD, с привязкой к оригиналу |
| `update(name, table, lineId: integer[], line: string): void` | Заменить каждую из указанных строк одним и тем же значением `line` |
| `getAll(name, table): string[]` | Прочитать все строки файла в пределах настроенных лимитов |

`name` и `table` во всех методах — строки. Нумерация строк начинается **с 1**;
пустые строки тоже учитываются. Возвращаемые строки не содержат разделителей
LF/CRLF. Пробелы внутри и по краям содержимого сохраняются.

- `get` с `countLine=0` или началом за концом существующего файла возвращает `[]`.
  Отрицательные значения и `lineId=0` — ошибка.
- `insert` и `update` принимают одну строку без CR, LF и NUL. Пустая строка допустима.
  `insert` добавляет LF; если прежняя последняя строка не завершена LF, сначала
  добавляется разделитель. Кампания должна существовать.
- `search` учитывает регистр и сохраняет порядок и повторы. Регулярные выражения
  не интерпретируются. Пустой `q` находит все строки. Совпадений нет — `[]`;
  отсутствующий файл или ошибка `grep` — ошибка MCP. Shell не используется.
- `update` игнорирует повторяющиеся ID; пустой список не меняет файл. Если хотя бы
  один ID недопустим или выходит за конец файла, исходный файл остаётся целым.
  Сохраняются исходные LF/CRLF, отсутствие последнего разделителя и права доступа.
- Чтение и обновление отсутствующей таблицы завершаются ошибкой. Только `insert`
  создаёт таблицу. `new` создаёт только каталог кампании.

Дополнительно сохранены `health_check`, ресурс `server://info` и prompt
`diagnose_server` для проверки соединения.

## Поиск с пагинацией

Первый вызов `searchPage`:

```json
{"name": "Кампания", "table": "журнал", "q": "ключ", "limit": 20}
```

Структурированный результат:

```json
{
  "matches": [{"lineId": 42, "text": "Мария передала ключ."}],
  "nextCursor": "<opaque cursor>",
  "version": "<file version>"
}
```

Передайте `nextCursor` как `cursor` следующего вызова с теми же `name`, `table`
и `q`. `limit` можно менять; он должен быть от 1 до `MCP_MAX_RESULT_LINES`.
`nextCursor: null` означает конец результатов. Порядок строк и повторы сохраняются.
Пустой `q` находит все строки. Поиск буквальный, регистрозависимый, без shell.

Страница может содержать меньше `limit` совпадений из-за лимита байтов: ориентируйтесь
на курсор, а не длину массива. Если отдельная совпавшая строка превышает лимит,
возвращается ошибка. После изменения файла старый курсор отклоняется: начните
поиск заново. `version` — отпечаток метаданных файла, а не хеш содержимого.

## Большие файлы

`get` и продолжение `searchPage` используют **разреженный индекс позиций строк**:
скрытый `.{table}.md.lines` содержит байтовую позицию каждой 256-й строки.
Первое обращение после строки 256 строит индекс одним полным проходом файла;
дальнейшие обращения переходят к ближайшей позиции и пропускают не более 255 строк.
Чтение ограничено буферами до 1 МиБ даже для отдельной строки огромного размера.
Индекс сохраняется между запусками; размер — примерно 8 байт на 256 строк + заголовок.

Индекс привязан к устройству, inode, размеру, `mtime_ns` и `ctime_ns` исходника.
После `insert`, `update` или обнаруженного внешнего изменения он перестраивается
при следующем обращении к дальним строкам. Пока это полная перестройка, без
инкрементального обновления при append. Повреждённый заголовок или усечённый индекс
перестраивается автоматически. Кеш можно удалить при остановленном сервере.
Сам `insert` проверяет последний байт и дописывает данные, не читая остальной файл.

`update` переписывает файл через временный файл в том же каталоге, используя
буферы до 1 МиБ даже для очень длинной отдельной строки. После проверки всех ID
выполняется атомарная замена. Требуется свободное место для новой версии файла.
При ошибке записи исходник сохраняется, временный файл удаляется; аварийное
завершение процесса может оставить скрытый `.mcp-*.tmp`.

Для согласованности параллельных вызовов используются POSIX-блокировки на
скрытом файле `.{table}.md.lock`: чтение разделяемое, запись исключительная.
Блокировки действуют между экземплярами и процессами этого сервера;
внешние редакторы, не использующие эти блокировки, не синхронизируются.

`search` запускает системный `grep` и читает его stdout построчно. SDK MCP
возвращает массив целиком, поэтому `get`, `getAll` и `search` ограничены
`MCP_MAX_RESULT_BYTES` и `MCP_MAX_RESULT_LINES`. Превышение вызывает явную ошибку,
**частичный результат не возвращается**. Для больших файлов используйте
`get` небольшими порциями, а для поиска — `searchPage`. Лимиты можно
увеличить в `.env`; у MCP-клиента также есть собственные ограничения ответа.
Лимит байтов относится к данным строк, а не к размеру JSON-конверта MCP.

## Recall и QMD

`recall` использует отдельный [QMD CLI](https://github.com/tobi/qmd). Python-сервер
работает в venv; QMD устанавливается отдельно. Новые версии QMD требуют Node.js 22+;
QMD 0.9.0 запускается через Bun 1.x. Проверяйте требования установленной версии.
Локальная установка из каталога проекта:

```bash
npm install --prefix .tools/qmd --no-audit --no-fund @tobilu/qmd
./.tools/qmd/node_modules/.bin/qmd --version
```

Укажите в `.env`:

```dotenv
MCP_QMD_COMMAND=./.tools/qmd/node_modules/.bin/qmd
MCP_QMD_MODE=query
MCP_QMD_CACHE_HOME=./.cache
MCP_QMD_TIMEOUT=300
```

Можно заранее загрузить модели из обычного терминала:

```bash
./.tools/qmd/node_modules/.bin/qmd pull
```

QMD 0.9.0 хранит модели в `~/.cache/qmd/models` и не учитывает `XDG_CACHE_HOME`
для этого пути. Настройка `MCP_QMD_CACHE_HOME` не переносит модели этой версии.
При первом семантическом запросе QMD также может загружать модели. Это требует сети,
места на диске и времени; для большой кампании увеличьте таймаут, а также таймаут
вызова у MCP-клиента. `MCP_QMD_MODE=search` включает только BM25 без этапа `embed`;
это явно отражается в ответе как `backend: "qmd:search"`. Автоматического переключения
на другой алгоритм при ошибке нет. Отсутствие QMD не мешает файловым методам.

```json
{"name": "Кампания", "q": "кто знает о тайном проходе", "limit": 5}
```

Форма результата:

```json
{
  "matches": [{
    "table": "персонажи",
    "startLine": 12,
    "endLine": 14,
    "startByte": 800,
    "endByte": 1050,
    "text": "<точный фрагмент исходного файла>",
    "score": 0.87,
    "version": "<file version>"
  }],
  "backend": "qmd:query",
  "truncated": false
}
```

`limit` — от 1 до `min(100, MCP_MAX_RESULT_LINES)`, `q` — непустая одна строка.
Номера строк начинаются с 1; смещения — байты UTF-8 с 0, `endByte` не включается.
`text` сохраняет исходные LF/CRLF. Длинная строка может занимать несколько фрагментов
с одинаковыми номерами строк; точный диапазон в таком случае задают байты.
`score` передаётся из QMD и служит ранжированию, а не вероятности истинности.

Перед поиском сервер сверяет версии файлов и потоково пересоздаёт фрагменты
изменившихся таблиц. Фрагмент содержит до 64 строк и примерно 8 КиБ; размер может
превысить настройку максимум на 3 байта, чтобы не разрывать UTF-8 символ.
В `{BASE_DIR}/{name}/.mcp-recall/` находятся производные Markdown-фрагменты,
SQLite-манифест с исходными диапазонами, конфигурация и отдельный индекс QMD.
Индексы кампаний изолированы; кеш моделей общий. После синхронизации выполняется
`qmd update`, в режиме `query` также `qmd embed`, затем запрос. Неизменившаяся
кампания использует уже построенный индекс. При изменении таблицы её фрагменты
пересоздаются полным проходом; фонового индексатора пока нет.

Первый вызов для большого архива может быть долгим. Обработка файлов в Python
потоковая, но производные фрагменты и индексы требуют дополнительного диска;
память моделей и самого QMD не ограничивается лимитом ответа MCP.
При превышении лимита байтов возвращается меньше результатов с `truncated: true`;
слишком большой первый фрагмент вызывает ошибку. Текст результата перечитывается
из оригинала, его версия проверяется; изменение найденного файла во время запроса
вызывает ошибку с предложением повторить `recall`.

## Архитектура

```text
src/gpt_parser_mcp/
├── __main__.py          # python -m gpt_parser_mcp
├── cli.py               # аргументы, логирование, выбор транспорта
├── config.py            # типизированные настройки и валидация
├── server.py            # create_server(): сборка и внедрение зависимостей
├── services/status.py   # прикладная логика и модель результата
├── services/markdown.py # потоковый файловый ввод-вывод, grep и блокировки
├── services/line_index.py # постоянный разреженный индекс строк
├── services/recall.py   # фрагменты, SQLite-манифест и QMD CLI
├── services/models.py   # типизированные результаты поиска
├── services/errors.py   # прикладные ошибки
├── tools/health.py      # MCP tool health_check
├── tools/markdown.py    # файловые методы и поиск MCP
├── resources/info.py    # JSON resource server://info
└── prompts/diagnostics.py  # prompt diagnose_server
tests/                  # конфигурация, MCP-контракты и запуск процесса
```

`create_server()` создаёт независимый экземпляр сервера; импорт модулей не
открывает порт и не запускает цикл обработки. Сервисы не зависят от MCP.
Обработчики tools/resources/prompts получают зависимости при регистрации.
Встроенный `health_check` проверяет только отклик процесса и возвращает
`status`, `name`, `version`; `server://info` публикует те же данные.

Чтобы добавить функциональность:

1. Реализуйте прикладную логику в `services/`.
2. Добавьте типизированный обработчик в `tools/`, `resources/` или `prompts/`.
3. Подключите регистрацию в `__init__.py` соответствующего модуля, а зависимости
   создайте в `server.py`.
4. Проверьте результат через SDK-клиент в `tests/`.

SQLite-манифест и процессы QMD открываются на время вызова `recall` и закрываются
после него. Для долгоживущих общих соединений используйте
[lifespan сервера](https://py.sdk.modelcontextprotocol.io/handlers/lifespan/).
Интеграция с соседним парсером остаётся следующим прикладным шагом.

## Проверки

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
python -m pip check
```

Используется стандартный `unittest`; отдельная тестовая зависимость не нужна.
Тесты проверяют файловые операции, ограничения ответа, сохранность при ошибках,
одновременную запись, защиту путей и ограниченное потребление памяти на файле
с одной строкой размером 24 МиБ. Контракты всех методов проверяются через
SDK-клиент, stdio из другой рабочей папки и Streamable HTTP через ASGI
без открытия сетевого порта. Дополнительно проверяются сохранение и инвалидирование
индекса строк, пагинация без потерь, ограничения страниц и соответствие фрагментов
`recall` исходным строкам и байтам.

В автоматических тестах `recall` используется явно обозначенный CLI test double
из `tests/fixtures/`: он проверяет запуск процессов, аргументы, изоляцию индексов,
обновление и ошибки, **но не проверяет качество семантического поиска QMD**.
Для проверки реального QMD установите его, задайте настройки выше и вызовите
`recall` через MCP-клиент на небольшой кампании с известными фактами.
